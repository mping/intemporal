Provision with a state machine

A workflow driven by an explicit finite state machine. The workflow suspends waiting for the next event; click a transition button to emit it and advance the machine. State is persisted, so the workflow replays from history — reload the page and it resumes where you left off. Use Clear to reset.

State machine — VM provisioning lifecycle

Two kinds of states: user-driven (the workflow waits for a button click) and I/O (an activity runs I/O and emits the next event). The rules are plain data. 


(def provision-rules
  {:state/init          [{::fsm/event :event/provision      ::fsm/to :state/provisioning}]
   :state/provisioning  [{::fsm/event :event/provisioned    ::fsm/to :state/attaching}
                         {::fsm/event :event/error          ::fsm/to :state/failed}]
   :state/attaching     [{::fsm/event :event/attached       ::fsm/to :state/booting}
                         {::fsm/event :event/error          ::fsm/to :state/deprovisioning}]
   :state/booting       [{::fsm/event :event/booted         ::fsm/to :state/running}
                         {::fsm/event :event/error          ::fsm/to :state/detaching}]
   :state/running       [{::fsm/event :event/halt           ::fsm/to :state/halting}]
   :state/halting       [{::fsm/event :event/halted         ::fsm/to :state/detaching}]
   :state/detaching     [{::fsm/event :event/detached       ::fsm/to :state/deprovisioning}]
   :state/deprovisioning [{::fsm/event :event/deprovisioned ::fsm/to :state/done}]
   :state/done          []
   :state/failed        []})

Activities

Each I/O activity handles its own errors and returns a map with :event (the next FSM event) plus any data produced. 


(defn provision-vm! []
  (try (maybe-fail! :provision) {:event :event/provisioned :instance-id "i-demo"}
       (catch js/Error _ {:event :event/error})))

(defn attach-volume! [instance-id]
  (try {:event :event/attached :volume-id "vol-demo"}
       (catch js/Error _ {:event :event/error})))

;; :state/init and :state/running pause for a user button click:
(defn apply-transition [rules current-state]
  (render-all!)
  (js/Promise. (fn [resolve _] (reset! pending-resolve resolve))))

Workflow — a loop driven by the FSM

I/O stubs are called inside a bloop. Each returns {:event <kw> & data}; the event drives fsm/transit and data merges into ctx so downstream activities receive ids from upstream ones. 


(defn-workflow run-fsm-workflow [rules init-state]
  (let [get-next-event (intemporal/stub #'apply-transition)
        provision-vm   (intemporal/stub #'provision-vm!)
        attach-vol     (intemporal/stub #'attach-volume!)]
    (bloop [current init-state ctx {}]
      (let [transitions (get rules current)]
        (if (empty? transitions)
          current                                       ; terminal state
          (let [[evt ctx']
                (case current
                  :state/provisioning (let [r (provision-vm)]
                                        [(:event r) (merge ctx (dissoc r :event))])
                  :state/attaching    (let [r (attach-vol (:instance-id ctx))]
                                        [(:event r) (merge ctx (dissoc r :event))])
                  ;; ... other I/O states ...
                  [(get-next-event rules current) ctx])] ; user-driven states
            (p/recur (::fsm/state (fsm/transit {::fsm/rules rules ::fsm/state current} evt))
                     ctx')))))))

Persistence & replay

History is saved to localStorage, so reloading the page rebuilds the engine from saved history and the workflow replays to its current state — resuming where you left off. Clear resets it.
